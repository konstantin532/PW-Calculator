# Исходные наборы свойств и скорость оружия

Дата сверки: 03.11.2026. Источники — публичный API mypers и локальный снимок
Comeback `/db/146/`. Современный каталог mypers в калькулятор не импортируется.

## Что содержится в sidecar

`data/catalog_defaults.json` содержит:

- `profiles`: редактируемые исходные наборы дополнительных свойств;
- `weapon_speeds`: отдельно сверенные значения базовых атак в секунду;
- `property_corrections`: индивидуальные поправки повреждённых строк источника;
- `coverage`: число совпадений и причины отклонения остальных записей.

Это наборы для планирования, **не объявление всех свойств гарантированными**.
Пользователь может менять выбранные свойства. Непустой сохранённый выбор нельзя
заменять этим набором при загрузке сборки.

Каждый профиль связывается с предметом по точному `pw_id`, затем проверяется
его ячейка и доступность десяти классов. Переносимые свойства должны иметь
распознанный тип и допустимое точное значение в вариантах именно предмета 1.4.6.
Неизвестный тип, неизвестное число и несовпадающее значение предложенного
свойства отклоняют профиль целиком. Число выбранных свойств ограничено `count`
с учётом постоянных `unique` с вероятностью 100%. Постоянные свойства не
копируются повторно.

Допускается одно узкое исключение для лишних свойств оригинала: если тип
известен, но такого свойства вообще нет в вариантах 146, его можно исключить
только когда оставшиеся точные совпадения заполняют **все** доступные
редактируемые места 146. Исключённые свойства прозрачно записываются в
`source.ignored`, их числа не попадают в расчёт. Неполный остаток отклоняется.
Свойство, которое предлагается в 146, исключать ради подгонки количества нельзя.

Диапазон исходной базы сохраняется диапазоном выбора: например,
`Интеллект +14~15` и исходное выбранное 15 дают `Интеллект +15`.
Неоднозначный тип и неизвестное число не превращаются в ноль.

Каждая запись содержит исходные API URL, тип, внутренний ID mypers, игровой ID,
SHA-256 полного ответа API, URL и хеш карточки Comeback. Сырые ответы API
остаются в игнорируемой папке `.cache/bonus-parity-original/`.

## Контрольные примеры

У [кольца 26389](https://comeback.pw/db/146/item/26389) исходный API группы `oq`
содержит запись `id174`, `pw_id26389` с одновременно выбранными `ci6`, `ed3`,
`ad2`. Они точно соответствуют строкам 146: `Время пения -6%`, `Крит +3%`,
`Показатель атаки +2`. Знак пения переносится из семантики `ra()/dv()` оригинала:
положительное `ci6` означает уменьшение времени пения на 6 процентных пунктов.

У [брони 9345](https://comeback.pw/db/146/item/9345) восстановление HP отличается:
оригинал выбирает `cx10`, единственная фиксированная строка 146 даёт 20.
Это единственное индивидуальное исключение: применяется строка 146
`Скор. восст. HP +20`, а `source.corrections` записывает исходное 10,
применённое 20 и причину. Правило ближайшего значения для других вещей
не используется; диапазон 19–20 также не подходит под это исключение.

Метеор 33533 в оригинале имеет только постоянный `Урон монстрам +60`.
Его случайные характеристики не выбираются автоматически.

У мантии 25718 оригинал выбирает пять свойств, а база 146 ограничивает число
тремя, предлагая все пять вариантов: здоровье 180, крит 1%, телосложение 6–10,
физзащиту 2% и магзащиту 4%. Эти проценты **есть в 146**. Поэтому профиль
отклонён из-за превышения количества; произвольный выбор трёх из пяти и
объявление процентов современными исключениями не допускаются.

## Ранг в исходном поле скорости

В карточках 146 поле `stats.atk_speed` может содержать **ранг**, даже если число
не превышает 5. Например, у [оружия 22](https://comeback.pw/db/146/item/22)
хранится 4, совпадающее с рангом 4. Это нельзя интерпретировать как 4 атаки/сек.

Отдельное соответствие API: `pw_id22`, `id560`, `sy1.11`, базовая физическая
атака 131–196 и отсутствующая магическая атака. Обе границы совпадают с 146.
Для меча 12647 совпадают физическая 663–995 и магическая 1212–1481 при `sy1.25`.
Для Метеора 33533 совпадают 456–684 и 831–1016 при `sy1.25`; этот ID также имеет
ранее предоставленное пользователем игровое подтверждение.

Генератор принимает скорость только при совпадении **обоих** диапазонов атаки,
точного игрового ID и корректном числовом `0 < sy <= 5`. Противоречащие записи
одного ID отклоняются. В `source.corrections.atk_speed` сохраняются исходное
значение, применённая скорость, область одного ID и ссылка на проверку.
Универсальная конверсия ранга в скорость не применяется.

**BLOCKED — независимая игровая сверка всех скоростей.** Совпадение базовых
атак и данных оригинального калькулятора является основанием для переноса
его значения, но не заменяет замер атак в секунду в клиенте Comeback.

## Индивидуальные поправки уменьшения магического урона

У 20 пар сапог и двух шлемов 146 исходные строки содержат аномальные значения
`Уменьшение урона от стихий +1022739087%` либо `+1028443341%`.
Их значение не выводилось из побитового представления числа. Для каждого из 22
разрешённых ID отдельно найден исходный предмет mypers с тем же `pw_id`.
Сверены базовые HP, физическая защита и все пять защит стихий. Только при
полном совпадении берётся явно выбранное оригиналом `ia3` или `ia5`.

Например, сапоги 32965 имеют с обеих сторон физзащиту 533 и каждую защиту
стихии 827; оригинал выбирает `ia3`, поэтому поправка этой строки составляет 3%.
У сапог 35737 совпадают физзащита 603 и каждая защита стихии 897, оригинал
выбирает `ia5`, что подтверждает поправку 5%. Шлемы 36997 и 37028 совпадают
по базовым HP 500 и 280 соответственно, при нулевых базовых защитах и `ia3`.

В `property_corrections` сохранены исходная и применённая строки, ID и URL
оригинала, хеш API, URL/хеш 146 и все сверенные базовые показатели.
Изменившаяся база, неизвестная исходная строка, противоречащий `ia` или любой
другой ID не проходят проверку. Исходный `catalog_items.json` не переписан.
Для формирования профилей генератор использует исправленную копию вариантов.
Распознанное после поправки свойство участвует в ограничении `count`;
оно не исключается ради сохранения слишком большого набора оригинала.

## Покрытие снимка

Получены все 13 групп обычной экипировки: `ft/rv/tg/rx/mj/wy/vx/st/oq/ta/qn/it/ic`.
В них 6509 исходных записей; после проверки ID, ячейки и класса 4466 совпадений
с 146. Принят 1541 редактируемый профиль, включая кольцо 26389, и 1625 скоростей
оружия. Для 32 записей скорости не перенесены из-за расхождения базовой атаки.
Все 1541 профиль прошёл `validateEquipmentChoice` текущего JavaScript-движка.
У 4 принятых наборов исключены 4 свойства, отсутствующие в вариантах 146;
каждый такой остаток полностью заполняет допустимое число редактируемых мест.

Основные причины пропуска наборов:2001 ID отсутствует в снимке 146,
1934 записи без выбранного набора,624 набора превышают допустимое число
свойств,150 имеют несовпадающие значения,24 — неизвестный тип. У 55 наборов
после исключения лишних свойств осталось недостаточно точных совпадений.
Ещё 127 не содержат редактируемых свойств после отделения постоянных и лишних.
Все счётчики и хеши доступны в `coverage`; причины не заменены догадками.

Два дополнительных соответствия проверены по точным игровым ID оригинала:
`Удар +50%` у колец 36539/43506 означает `ae_eg` — процент меткости, а
`Иммунитет к физическому урону +3%` трактата 17627 означает `bu3`.
Первое не превращается в физическую атаку; второе не означает полную неуязвимость.
Эти подписи учитываются при сравнении вариантов, поэтому их нельзя ошибочно
отбросить как отсутствующие в 146 ради освобождения мест.

## Воспроизведение

Работа только с ранее сохранёнными ответами:

```powershell
.venv\Scripts\python.exe -m tools.mypers.equipment_defaults --cache .cache/bonus-parity-original
.venv\Scripts\python.exe -m pytest tests/test_equipment_defaults.py -q
```

Явное обновление публичных API перед построением:

```powershell
.venv\Scripts\python.exe -m tools.mypers.equipment_defaults --fetch --cache .cache/bonus-parity-original
```

Без `--fetch` сеть не используется. Исходные `catalog_items.json` и
`catalog_stones.json` генератор не изменяет. Изменившиеся ответы mypers могут
изменить покрытие; хеши позволяют отличить новый снимок от проверенного.
