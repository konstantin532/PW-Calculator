# Современная PWDB и клиент Comeback PW 1.4.6

Проверены **9 карточек**, получены **9 ответов HTTP 200**. Новые предметы
не импортировались; runtime-каталоги и клиент игры не изменялись.
Рядом находятся автономный [HTML-отчёт](pwdb-reference-comparison.html)
и [CSV с теми же строками](pwdb-reference-comparison.csv).

## Как получены данные

Это первичные ответы самого сайта, а не пересказ сторонней вики.
Официальный SPA-модуль карточки вызывает
`GET https://pwdatabase.ru/api/v1/items/{id}`. Перед открытием приложения
главный JS сайта выполняет пустой `POST /api/v1/auth/frontend`. Использован
тот же штатный анонимный bootstrap: входа в аккаунт нет; cookies остаются
только в памяти процесса. Заголовки, cookies и токены не печатаются
и не сохраняются. Кеш содержит только карточки предметов и URL/status/hash.

Исследованные публичные файлы:

| Файл | SHA-256 |
|---|---|
| `index-DZAZc6hE.js` | `a3f5906d7e8a45dfe432cd24db81a2f7f81b05d42e06a2cdd01ca2d5eb604ee4` |
| `detail-BaHAkfnz.js` | `6ad3c6c0b309295f53013b8c47382bd4c858f4c91ef7f08f0792656f679e7b34` |

Большой JS сначала обрывался при передаче. Обычные HTTP Range-запросы
с одинаковым ETag и проверенными Content-Range позволили прочитать файл
полностью. Обхода авторизации или CAPTCHA не применялось.

## Камень25154: первичная клиентская проверка

В рабочей копии клиента с SHA-256
`86c649d928c1707ea8100e5849fa4edad75cc372c2daba85e0bca0d6c6f0813a`
найдена запись `STONE_ESSENCE` по первичной схеме PW1.4.6 v80:

| Поле | Смещение | Значение |
|---|---:|---|
| Начало записи/ID | 11611858 | 25154 |
| id_sub_type | 11611862 | 12636 |
| Name | 11611866 | Камень лагеря |
| level | 11612186 | 13 |
| id_addon_damage | 11612210 | 2309 |
| id_addon_defence | 11612214 | 2310 |
| weapon_desc | 11612218 | Защита +2 |
| armor_desc | 11612250 | Защита +2 |

Имена, уровень, цены и оба описания согласуются с карточками.
Следующая запись на границе436 байт начинается с ID38155 и того же
subtype12636. Это точечное чтение одной записи; весь список камней
данным исследованием не разобран.

В уже строго разобранной таблице `EQUIPMENT_ADDON` оба ID2309/2310
имеют один параметр2. Первичная
[таблица addon→type](https://github.com/Wrechid/sELedit-/blob/2529c280f19912b0088f1db3bd6d268bf7fec802/sELedit/bin/Debug/resources/data/addon_table.txt)
даёт им обоим тип60, а
[форматтер](https://github.com/Wrechid/sELedit-/blob/2529c280f19912b0088f1db3bd6d268bf7fec802/sELedit/COMMON/GetProps/EQUIPMENT_ADDON.cs#L264)
определяет60 как Def.Level. Поэтому русское сокращённое «Защита»
в старом описании можно разрешить в **defense_level**, не угадывая по имени.

## Что не установлено

- Современный PWDB не расшифровал851/888: он возвращает те же внутренние
  названия камней, что клиент, и не раскрывает тип числового эффекта.
- Клиентские пользовательские6000–6011 не встречаются в этих карточках.
  Их совпадение с современной официальной базой не объявляется.
- Семь основных карточек не дают основания объявлять современную PWDB
  точной для всех предметов1.4.6. Два дополнительных кольца уже показывают
  изменение требований.
- Новые классы, карты и современные вещи не переносились.

## Воспроизведение

Из существующего кеша, без сети:

```powershell
.venv\Scripts\python.exe -m tools.research.pwdb_compare
```

Повторное чтение только девяти разрешённых карточек:

```powershell
.venv\Scripts\python.exe -m tools.research.pwdb_compare --fetch
```

Скрипт требует, чтобы все ID уже существовали в локальном каталоге1.4.6,
проверяет SHA-256 кешей и ID ответов, затем создаёт только HTML/CSV.
Реально выполнено: офлайн-сверка9 карточек и проверка Ruff. Изменений
игрового клиента или рабочих каталогов от этого исследования нет.
