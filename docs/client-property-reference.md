# Свойства предметов из клиента Comeback PW 1.4.6

Клиент прочитан без запуска игры и без изменения файлов. Рабочая копия
`elements.data` находится в игнорируемом `.cache/client-data`. Используется
проверяемый читатель `tools/client/elements.py`; источник и SHA-256 каждого
экспорта записаны в `data/catalog_client_properties.json`.

## Что установлено

У плаща **21418** веб-база показывает только силу 6–7 и число свойств 3.
В клиенте находятся пять ID: **1451, 1456, 1466, 1461, 333**, `fixed_props=2`,
а вероятности отдельных строк — **1, 0, 0, 0, 0**. Нулевая вероятность строки
в этом режиме не удаляет её из блока свойств.

Это согласуется с первичными исходниками:

- [sELedit ARMOR_ESSENCE](https://github.com/Wrechid/sELedit-/blob/2529c280f19912b0088f1db3bd6d268bf7fec802/sELedit/COMMON/GetProps/ARMOR_ESSENCE.cs#L173-L207)
  при ненулевом `fixed_props` и отсутствии гарантированного нулевого блока
  выводит каждый ненулевой ID, не фильтруя вероятность отдельной строки.
- [Генератор предметов](https://github.com/huzeming/176source/blob/c0992a29c0848de4de139a8958ceb11edcf2d38b/cgame/gs/item/itemdataman.cpp#L171-L203)
  при ненулевом входном числе свойств проходит весь фиксированный список,
  пропускает нулевые ID и заменяет число свойств фактическим количеством.
  Это публичный исходник более позднего сервера, используемый как
  независимое подтверждение поведения, а не как источник значений 1.4.6.
- [Таблица ID → тип](https://github.com/Wrechid/sELedit-/blob/2529c280f19912b0088f1db3bd6d268bf7fec802/sELedit/bin/Debug/resources/data/addon_table.txt)
  и [форматтер](https://github.com/Wrechid/sELedit-/blob/2529c280f19912b0088f1db3bd6d268bf7fec802/sELedit/COMMON/GetProps/EQUIPMENT_ADDON.cs)
  определяют смысл параметров и единицы. Внутренние имена вроде `A_H007`
  не используются для угадывания типа.

| Предмет | Режим | Клиентский блок |
|---|---:|---|
| 21418, Плащ прочности·Долина бога | 2 | Сила, ловкость, телосложение, интеллект по 6–7; пение −6% |
| 25718, Мантия мага небес | 3 | HP +180; крит +1%; телосложение +6–10; физзащита +2%; магзащита +4% |
| 26389, Длань управляющая тучами | 3 | Крит +3%; пение −6%; показатель атаки +2 |
| 14970, Браслет ветра | 2 | HP +80; пение −6%; уменьшение физического урона +1% |
| 33533, Метеор | 0 | Случайный набор; фиксированное правило к нему не применяется |

**Интеллект и телосложение:** ID 1461 (`A_H007`) имеет тип 43 — интеллект;
ID 1466 (`A_I007`) имеет тип 44 — телосложение. ID 2273 у мантии 25718
также имеет тип 44 и сохраняет диапазон 6–10.

**Восстановление:** первичный форматтер делит целочисленные параметры
восстановления на два. У брони 9345 ID 324 имеет параметр 20 и означает
HP +10 в секунду; исходный mypers также показывает 10. Значение +20 в
веб-карточке 146 не используется поверх более точных клиентских данных.

## Контракт слоя данных

Экспорт содержит все именованные предметы существующего каталога, которые
найдены в первых трёх таблицах экипировки и имеют ненулевой `fixed_props`.
Сначала сверяются ID и имена с нормализацией только пробелов.

- `raw_count_probabilities` и `fixed_props` остаются исходными.
- `addon_count` в фиксированном блоке равен числу ненулевых ID, включая
  одинаковые типы и повторные ID. Это не число разных названий.
- При `P(count=0)=1` активный список пуст и имеет число 0. Исходные ID
  сохраняются отдельно в `non_generating_addons`.
- `source_required`/`guaranteed` означают отсутствие варианта нулевого блока.
  Они не выбирают максимальный бросок: `min` и `max` сохраняются раздельно.
- У строки сохраняются ID, исходные параметры, точная вероятность и тип.
  Проценты декодируются из float32 только у доказанного процентного типа.
- Нерасшифрованные свойства имеют `stat/min/max=null`, читаемый ID и исходное
  внутреннее имя. Число навыка не превращается в пассивную прибавку.
- Случайные пулы режима 0 по умолчанию не публикуются в этом слое и не
  заменяют существующие варианты. Полный исследовательский экспорт можно
  получить отдельно через `--include-random`.

Полные чужие таблицы и клиентские бинарные файлы не добавляются в Git.
Типовая таблица загружается только по явному флагу, с закреплённым git blob
и SHA-256; значения свойств берутся только из закреплённого клиента.

## Покрытие и проверка

Проверен каталог из **6546** записей. **5050** именованных записей совпали
с разобранными клиентскими таблицами; **1294** пустых служебных записей
исключены. **202** записи относятся к другим таблицам (**109** трактатов,
**62** боеприпаса, **31** полёт) и не исправляются этим экспортом.

В слой вошли **2535** фиксированных предметов: **2255** полностью числовых,
**280** с явно отмеченными нерасшифрованными эффектами. У **756** именованных
предметов фиксированный клиентский блок длиннее ошибочного ограничения
веб-источника. У **44** именованных фиксированных записей вероятность нулевого
блока равна 1; в 42 из них список ID и так пуст, оставшиеся два — GM-предметы.

Активные фиксированные блоки содержат **8072** строки: **7795** числовых,
**260** эффектов навыков и **17** иных нерасшифрованных свойств. Последние
**277** строк затрагивают **277** предметов. Их значения остаются неизвестными
и не добавляются к характеристикам. Три из 280 неполных исходных описаний
относятся к неактивным блокам с вероятностью нулевого набора 1.
Записи случайных пулов и неиспользуемые `rands`/`uniques` фиксированных вещей
учитываются отдельно в общем аудите `coverage` и не подменяют игровой расчёт.

Воспроизведение на извлечённой рабочей копии:

```powershell
.venv\Scripts\python.exe -m tools.client.elements --elements .cache/client-data/elements.data --output .cache/client-data/item-inputs.json
.venv\Scripts\python.exe -m tools.client.properties --inputs .cache/client-data/item-inputs.json --fetch-type-table
.venv\Scripts\python.exe -m pytest tests/test_client_properties.py -q
```

При повторном запуске с уже сохранённой таблицей флаг `--fetch-type-table`
не нужен. Сам генератор свойств не читает, не изменяет и не запускает игру.
