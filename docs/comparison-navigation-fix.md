# Переход между одним и двумя персонажами

Проблема: короткая кнопка «Сравнить» находилась в общей панели действий.
«Один персонаж» открывал другую страницу; при новом входе в сравнение правая
сборка создавалась заново. Это воспроизведено на порту 8000: имя второго
«Второй для возврата» менялось на «Без имени».

Исправление: отдельная кнопка «Сравнить с другим персонажем» над обычным
калькулятором. В сравнении «Один персонаж» теперь только скрывает правую панель,
а повторное нажатие возвращает её. Страница и оба калькулятора не перезагружаются.
Копирование и таблица скрыты в одиночном режиме и возвращаются вместе с правой панелью.
Ссылки «Открыть отдельно» ведут на обычный калькулятор с кнопкой сравнения.

Проверить цикл два → один → два, несколько повторений, редактирование левого
в одиночном режиме, сохранность правого и доступность кнопок на узком экране.
Формулы, экипировка и формат сохранений не меняются.

## Проверка

- На 8000 выполнены три цикла два → один → два: ни одного перехода или
  перезапуска iframe, правые имя, характеристики, репутация, экипировка и показатели сохранены.
- Изменения силы первого персонажа 25 → 26 → 27 в одиночном режиме сохранились.
- Кнопка возврата полностью видна на ширинах 360 / 390 / 719 / 1440 px;
  переполнения нет, повторные переключения сохраняют второго персонажа.
- В репозитории: 85 JavaScript + 57 Python = 142 теста. В рабочей копии:
  85 JavaScript + 58 Python = 143 теста (один дополнительный локальный тест).
- Django check, Node syntax, Ruff и git diff --check прошли; ошибок и предупреждений
  браузера нет. Независимый просмотр кода не выявил блокирующих замечаний.
