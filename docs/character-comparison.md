# Два независимых калькулятора персонажа

Запрос: второй такой же калькулятор рядом с первым для сравнения персонажей.
Оформление, десять классов, каталог 1.4.6 и условная активация экипировки сохраняются.

## Интерфейс

- Отдельная кнопка «Сравнить с другим персонажем» над обычным калькулятором открывает `/compare/`.
  Текущая сборка передаётся первому персонажу; второй начинает с обычного нового персонажа.
- Две полноценные панели с собственными бафами, классом, полом, уровнем,
  репутацией, атрибутами, экипировкой и действиями сохранения/загрузки.
- На широком экране панели стоят рядом, на узком — одна под другой.
- Кнопки «1 → 2», «2 → 1» и обмен сборками позволяют сравнивать варианты.
  Подписи поясняют, что копирование заменяет сборку получателя.
- Таблица показывает значения обоих персонажей и разницу «2 − 1».
  Для времени пения меньшее значение лучше. Цвет дополняет числа и знаки.
- «Один персонаж» скрывает правую панель без перехода на другую страницу.
  На том же месте появляется «Сравнить с другим персонажем», возвращающая обе панели.
  Оба состояния сохраняются, включая изменения левого персонажа в одиночном режиме.

## Состав

Оба экземпляра используют существующий `index.html` на `/calculator/` в отдельных
документах iframe. Это сохраняет работающие калькулятор, окна выбора и локальные ID,
а состояние одного персонажа не затрагивает другого. Один и тот же движок и каталог
используются обоими экземплярами; формулы не дублируются.

`index.html` получает контекст `embedded=True` только на `/calculator/`.
У вложенной версии скрыты повторный переход в сравнение и нижний общий футер.
Её CSS сохраняет две игровые панели на ширине, достаточной для 657 px, и складывает
их на телефоне. Высота iframe подстраивается под содержимое без внутренних полос прокрутки.

## Контракт модулей

`static/js/engine/comparison.js` — чистые функции и константы:

- `STATE_MESSAGE = "pwcalc:comparison-state"`;
- `APPLY_MESSAGE = "pwcalc:comparison-apply"`;
- `createComparisonSnapshot(state, stats)` возвращает
  `{ name, className, level, metrics }`, где `metrics` содержит ключи из списка ниже;
- `isComparisonSnapshot(value)` проверяет строки, уровень и конечные числовые значения;
- `compareSnapshots(left, right)` возвращает строки
  `{ key, label, unit, left, right, delta, trend }`; `trend` — `better`, `worse`, `equal` или `mixed`;
- `encodeBuildHash(json)` возвращает `#build=...` в существующей UTF-8/base64url форме;
- `comparisonUrl(json)` возвращает `/compare/` + такой хеш;
- `COMPARISON_METRICS` — описание метрик `{ key, label, unit, better }`.

Метрики: `hp`, `mp`, `physAtk` (пара), `magAtkRange` (пара), `physDef`, `magDef`,
`crit`, `atkSpeed`, `castTime`, `attackLevel`, `defenseLevel`, `speed`.
`better` равен `lower` для `castTime`, иначе `higher`. Единицы: `%`, `уд/сек`, `м/сек`
для соответствующих значений, остальные без единицы.

`static/js/comparison-bridge.js` экспортирует
`createComparisonBridge({getPayload, onApply}) -> {publish}`.
Он действует только во вложенном калькуляторе. `getPayload()` даёт
`{build, snapshot, ready}`, где `build` — результат существующего `serializeBuild`.
Он отправляет родителю `{type: STATE_MESSAGE, build, snapshot, ready, height}`.
Обновления объединяются через requestAnimationFrame; изменение высоты отслеживается
по `.calc`, включая изменение ширины и содержимого. `height` — целое 320…12000.
Получение `{type: APPLY_MESSAGE, build}` вызывает существующий `applyBuild`,
который проверяет импорт по доверенному каталогу. До готовности каталога копирование отключено.

`comparison-page.js` принимает сообщения только от двух своих окон и своего origin.
Мост принимает команды только от родителя и своего origin. Строка сборки ограничена
1 МБ; неизвестные сообщения, неверные снимки и бесконечные числа игнорируются.
Тексты выводятся через textContent. Сырые данные экипировки не передаются между
калькуляторами: используется существующее компактное сохранение с ID и валидацией.

## Проверка и доставка

Проверочный список интерфейса:

- Повторно используется текущий `index.html`, а не вручную скопированные игровые панели.
- Существующие материалы и значения: `.jade-skin`, тёмный металл и нефрит,
  панель персонажа 320 px, экипировка 317 px, промежуток 20 px, полный калькулятор 657 px.
- Кнопки — нативные button, возврат — ссылка, два iframe имеют разные понятные title.
- Имена и вывод сообщений — textContent; ошибки видны текстом, цвет не единственный индикатор.
- На 1440 px две полноценные панели соседствуют без горизонтального переполнения;
  на 360 / 390 px оба персонажа последовательно доступны в одной колонке.
- Копирование недоступно до загрузки обоих каталогов; ошибка импорта не затирает текущую сборку.
- Только `/calculator/` разрешает SAMEORIGIN iframe; остальные страницы сохраняют DENY.
- Изменение имени публикуется сразу, даже если не вызывает пересчёт показателей.
- Автоматическая высота измеряется по `.calc`, а не по высоте самого iframe.

Проверить независимость обоих состояний, импорт/сохранение на нужной стороне,
копирование/обмен, разницу показателей, бафы и условные бонусы вещей, настольную
и мобильную геометрию, готовность каталога, ошибки сообщений и отсутствие рекурсии iframe.
Рабочая папка пользователя — `F:\PW-Calculator-main`, локальный сервер — порт 8000.
Перед переносом сохранить исходные файлы и локальные отличия этой копии.
